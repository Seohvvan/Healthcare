# 실험 결과 정리 (2026-08-18 ~ 08-20)

대화형 임상시험 추천 파이프라인(trialmatch)의 검증 실험 결과 요약.
원본 실행 로그(`runs/*.json`)와 데이터(`data/`)는 용량 문제로 git에서 제외되어
로컬에만 있으며, 이 문서가 그 요약본이다. 모든 실험은 `gemini-3.1-flash-lite`로
실행 (temperature 0, 판정 모델을 pro로 올린 비교 1회 포함).

## 시스템 한 줄 요약

환자 서술(자유 텍스트) → 프로필 추출 → BM25+RRF로 후보 50건 검색 →
선정/제외 기준을 원자 단위로 분해 → LLM이 기준별 충족/미충족/모름 판정(근거
인용 강제) → 순수 코드 집계·랭킹(적합 > 미정 > 제외 > 무관) → 모름 때문에
미정인 시험만 골라 환자에게 질문(최대 5개/라운드) → 답변 반영 후 해당 기준만
재판정 → 랭킹 갱신 → Top-K 리포트.

---

## 실험 1 — 질문 루프로 미정→적합 전환 (S005 데모)

**설정**: 대회 샘플 S005(조짐 편두통, 한 문장)를 입력, 손으로 작성한 정답
시트(`data/s005_ground_truth.txt`)를 환자 역할 LLM에게 주고 질문 3라운드.

**결과** (`runs/S005-sim3-20260818-074047.json`):

- 1라운드: 질문 5개 중 4개 답변됨 → 기준 38개 재판정
- 2라운드: 5개 중 3개 → 26개 재판정, 3라운드: 5개 중 1개 → 24개 재판정
- 최종: 전부 미정이던 랭킹에서 **적합 2건 확정** (NCT00123201, NCT03479060)
- 판정 근거에 시뮬레이터 답변이 원문 인용됨 (예: 제외 기준 "월 8회 초과 발작"
  vs 답변 "월 평균 4회" → 산술 비교로 미해당 확인)
- 정답 시트에 없는 정보를 물은 질문은 "모른다"로 답변되어 해당 기준이
  모름으로 유지됨 — 추측으로 메꾸지 않는 안전 동작 확인

## 실험 2 — masked-field: 질문 능력 정량화 (핵심 숫자)

**방법**: 샘플 환자 10명의 한 문장을 LLM으로 10~12문장의 완전한 가상
기록(허구 정답지)으로 확장(`data/masked_patients.json`, 코드
`trialmatch/eval/masked.py`) → 환자가 알 만한 사실(복약, 병력, 흡연 등)
하나를 지운 버전을 시스템에 입력 → 시스템이 질문하면 환자 역할 LLM이
완전판 정답지만 보고 답변(없는 정보는 "모른다" 강제) → 지운 사실을
되찾았는지 코드로 자동 채점. 비교군(완전판 실행)과는 질문 예산·후보
목록을 동일하게 통제.

**결과** (10명 × 사실 2개, 오류 0, `runs/masked-20260819-145352.json`):

| 지표 | 값 | 의미 |
|---|---|---|
| 회복률 | **9/20 (45%)** | 지운 사실을 시스템이 알아서 질문으로 되찾음 |
| 확정 전환 | **평균 3.55건/환자** | 답변 후 미정→확정으로 바뀐 임상시험 수 |
| top-1 라벨 보존 | **19/20 (95%)** | 정보를 가려도 1순위 추천이 유지됨 |
| 완전판 대비 라벨 일치율 | 0.695 | 문장 하나의 결손이 질문 경로를 바꿔 생기는 파급 포함 |

회복에 성공한 사실: 음주력, 피임 상태, 발작 빈도, 흡연력, 복약 상태 등 —
전부 환자가 경험으로 답할 수 있는 정보. 실패 원인은 대부분 질문 예산(5개)이
다른 미해결 기준과 경쟁해 밀린 경우.

**재현성**: 동일 입력 2회 실행 시 20개 시험 라벨 완전 일치 (일치율 1.0,
`runs/M001-nf-*.json`). 판정이 결정적으로 재현됨.

## 실험 3 — TREC 2021 공식 벤치마크 (외부 정답 기준)

**설정**: TREC CT 2021 topics 75개 + 전문가 판정(qrels) 35,832건 + 판정
당시(2021-04) 스냅샷 코퍼스 26,149건 (TrialGPT 배포본, 커버리지 99.9%).
과제: 토픽당 심사된 시험들을 재랭킹. LLM 실행은 비용상 토픽 10개 ×
후보 20건 샘플.

| 구성 | nDCG@10 | 3분류 정확도 | 미정 비율 |
|---|---|---|---|
| BM25만 (75토픽 전체) | 0.2896 | — | — |
| flash-lite 판정 (10토픽) | 0.2875 | 0.560 | 141/200 (70%) |
| 3.1-pro 판정 (같은 10토픽) | 0.2841 | 0.585 | 182/200 (91%) |

**해석**:

1. 질문할 상대가 없는 단발 과제에서는 보수적 판정("모르면 보류")이 순위
   변별력을 잃어 LLM이 BM25 대비 이득이 없음 — 대화형 시나리오(대회 환경)와
   대비되는, 설계상 예상된 트레이드오프.
2. 판정 모델을 pro로 올려도 개선 없음(미정만 증가) → **모델 등급은 병목이
   아님**. 이후 전 실험을 flash-lite로 통일한 근거.
3. 추가 진단: BM25 사전 랭킹이 유관 시험을 상위 20에 거의 공급하지 못함
   (토픽별 상위 20 내 유관 시험 0~13%; 토픽 8·10은 0건). LLM은 받은 후보
   안에서만 재정렬 가능하므로 **후보 공급이 다음 개선 표적**.

## 평가 방법론에서 얻은 교훈 (측정 장치 자체의 결함을 찾아 수정)

1. A/B 실행마다 검색 결과가 달라 비교가 오염됨 → 후보 목록을 두 실행이
   공유하도록 고정
2. 환자 역할 LLM이 검사수치까지 답하는 비현실적 오라클이라, 실제 환자
   기준으로 옳은 개선이 채점에서 감점됨 → 환자가 알 만한 정보만 알도록 정렬
3. top-k로 자른 랭킹 위에서 일치율을 재면 지표가 자동으로 부풀려짐 →
   무절단 랭킹으로 비교

전체 규칙은 `docs/lessons-learned.md` 참조.

## 재현 방법

```bash
# 오프라인 테스트 (API 불필요)
uv run pytest

# TREC BM25 기준선 (API 불필요, 데이터는 ftp.ncbi.nlm.nih.gov/pub/lu/TrialGPT 등에서 다운로드)
python -m trialmatch.eval.bench bm25 --topics-xml data/topics2021.xml \
  --qrels data/qrels2021.txt --trials data/trec_2021_corpus.jsonl

# masked-field 실험 (Gemini API 키 필요, .env에 GEMINI_API_KEY)
python -m trialmatch.eval.masked generate --topics synthetic-patients.json --out data/masked_patients.json --provider gemini
python -m trialmatch.eval.masked run --patients data/masked_patients.json \
  --trials data/trials.jsonl --index data/bm25.pkl --provider gemini --max-facts 2 --question-rounds 2

# 대화형 데모 (질문에 사람이 직접 답변)
python -m trialmatch run --note "환자 서술..." --patient-id DEMO \
  --trials data/trials.jsonl --index data/bm25.pkl --provider gemini
```

**주장 범위 주의**: TREC 수치는 2021-04 스냅샷 기준의 엔진 외부 검증이며,
대회 데이터 성능에 대한 주장이 아님. masked 수치는 "정답지에 존재하고 환자가
알 만한 정보"라는 조건에서의 질문 회복 능력임.
